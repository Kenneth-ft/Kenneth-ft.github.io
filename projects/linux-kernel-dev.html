Embedded Linux Device Tree & Drivers

Authored custom device tree nodes in the Linux kernel on an NXP i.MX8MM processor at Promag Enviro Systems to bind SPI and UART telemetry hardware with automated SSH deployment.

Company Promag Enviro Systems
Role Product Development Team
Processor NXP i.MX8M Mini (ARM Cortex-A53)
Environment Embedded Linux Kernel, Device Tree Source (DTS), SSH

Project Overview

Connecting custom hardware to an embedded Linux single-board computer requires communicating with the operating system at the kernel level. At Promag Enviro Systems, I configured Linux kernel device trees to describe non-discoverable SPI and UART hardware peripherals on a custom daughterboard, enabling user-space software to read telemetry reliably.

Device Tree Architecture & Driver Binding

  • Device Tree Source (.dts / .dtsi): Defined bus speed, chip select pins, interrupt request (IRQ) lines, and compatible driver bindings for on-board peripheral ICs attached to the i.MX8MM processor.
  • Kernel Module Verification: Compiled and loaded kernel drivers (spidev, serial drivers), ensuring proper pinmux allocation in the IOMUXC controller without pin contention.
  • Userspace Hardware Verification: Wrote C test utilities using ioctl() calls to transmit test packets across SPI and UART, confirming loopback integrity with a logic analyzer.

Automated Remote Development Toolchain

Configured an authenticated, secure SSH server directly on the target hardware. Built automated deployment scripts via Make and Git so firmware developers could cross-compile on host machines, push binaries over network sockets, and inspect live dmesg kernel ring buffers in real time.
